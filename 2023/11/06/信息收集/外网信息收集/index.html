总体思路

主要还是以获取权限为目的

自动化工具水泽、oneforall（会吞fofa的F点，适当修改下用它其它功能即可）（将两者api尽量补全）+ google搜索 + 公开库或历史泄露（GitHub、暗网）+ censys补全 + 结合其他在线网站或工具手动认证补全遗漏信息

一、目标特征收集

网站图标：ctrl+u 查看源码，一般会有（或fofa搜站点，也可以直接得到icon_hash）

title：F12 （用title作为关键词搜索，要多拆解、多尝试）

目标性质、产品、服务：熟悉浏览目标网站的每一个部分，看他是干什么的，提供什么服务产品，为谁服务

目标自己提供敏感信息：网站自己提供的联系方式、公司地址、邮箱

目标cms ：https://whatcms.org/ https://whatweb.net/ （常见或开源cms，可审计）

whois：http://whois.chinaz.com https://who.is/ https://viewdns.info/ https://www.whois365.com/cn/（获取注册人关键信息）

cdn对抗

CDN本来是目的用来加速的，但却起到了很好的安防效果。当目标使用了CDN加速，获取到的目标ip不一定是真实ip。所以通常在实施端口、漏扫等测试之前，需判断下是否真实IP，是否使用了CDN或其他代理等等，避免无效操作、蜜罐、非目标点。

CDN配置问题

某些站点只做了www cname到CDN上，导致www.xxx.com和xxx.com是两条独立的解析记录，所以可以通过直接ping域名xxx.com获取到未加入cdn的真实IP，同理http协议和https协议配置也是有可能出现这种问题。

漏洞

网站本身存在一些漏洞时，如XSS/SSRF/XXE/命令执行等，通过带外服务器地址注入，使服务器主动连接，被动获取连接记录。
部分本身功能，如url采集、远程url图片、编辑器问题等。
异常信息、调式信息等都有可能泄露真实IP或内网ip的。

邮件头信息

一般邮件系统都在内部，没有经过CDN解析，通过邮件发送、RSS订阅等sendmail功能去获取到服务器与邮箱系统交互的邮件源码，在源文件头信息或者源代码中就会包含服务器真实ip。但需注意该ip是否第三方邮件服务器（如腾讯企业邮件、阿里企业邮箱），一般只有应用与网站在同一服务器上时，才获取到当前服务器的真实ip。

常见交互功能点：
RSS 订阅
邮箱注册、激活处
邮箱找回密码处
产品更新的邮件推送
某业务执行后发送的邮件通知
员工邮箱、邮件管理平台等入口处的忘记密码

四、指纹信息收集

cms

识别思路：

特定文件的MD5
一般来说，网站的特定图标、js、css等静态文件不会去修改，通过爬虫对这些文件进行抓取并与规则库中md5值做对比，如果一致就是同一CMS。这种情况不排除会出现二开导致的误报，但速度较快。

页面关键字
正则匹配关键字或报错信息判断。如Powered by Discuz、dedecms等、tomcat报错页面

请求头信息关键字
通过匹配http响应包中的banner信息来识别。

如：
X-Powered-By字段
Cookies 特征
Server信息
WWW-Authenticate
Meta特征
……

url关键字
将url中存在路由、robots.txt、爬虫结果与规则库做对比分析来判断是否使用了某CMS

如：
wordpress默认存在目录：wp-includes、wp-admin
织梦默认管理后台：dede
帝国常用目录：login/loginjs.php
weblogic常用目录：wls-wsat
jboss常用目录：jmx-consol

插件漏洞

1）CVE-2021-24311 WordPress External Media Plugin 1.0.34之前版本的wp_ajax_upload-remote-file AJAX存在任意文件上传漏洞；

2）CVE-2021-24312 WordPress WP Super Cache Plugin 1.7.3之前版本的设置中的部分参数存在远程代码执行漏洞。该漏洞源于程序允许输入“$”和“\n”。攻击者可利用该漏洞导致远程代码执行；

3）WordPress的 InfiniteWP Client和WP Time Capsule插件在实现中存在高危身份验证绕过漏洞，利用这些漏洞，攻击者无需密码即可登录管理员帐户。（WordPress InfiniteWP Client < 1.9.4.5 WordPress WP Time Capsule Version < 1.21.16）

4）CVE-2017-1002000：wordpress插件中的漏洞mobile-friendly-app-builder-by-easytouch v3.0，文件中的代码./mobile-friendly-app-builder-by-easytouch/server/images.php不需要身份验证或检查允许用户上传内容。
CVE-2017-1002001：wordpress插件中的漏洞mobile-app-builder-by-wappress v1.05，该插件包含来自http://www.invedion.com的未经许可的易受攻击的CMS软件。

5）CVE-2015-8351 Gwolle Guestbook WordPress 1.5.3及更早版本，未有效过滤”abspath” HTTP GET参数值，即用在PHP require()函数中，远程攻击者可从任意远程服务器包含名为’wp-load.php’的文件，并在受影响的Web服务器中执行。

6）CVE-2015-1375 Pixabay Images 2.4之前版本，pixabay-images.php没有正确限制访问上传功能，远程攻击者利用此漏洞可对任意文件进行写操作。

7）WordPress插件BackWPup 2.1.4在job/wp_export_generate.php的BackWPUpJobTemp POST参数上缺少数据验证，可使攻击者指定FTP资源为输入，造成在Web服务器上执行本地或远程代码。

8）WordPress插件Simple:Press Forum在实现存在多个安全漏洞，可造成代码执行和泄露完全路径。 WordPress Simple:Press Forum 4.1.2

9）FeedWordPress插件在实现上存在sql注入漏洞，攻击者操纵sql查询逻辑，利用此漏洞对下层数据库执行未授权操作。

常见框架

spring-boot

1）默认图标和默认报错：小绿叶、Whitelabel Error Page

2）X-Application-Context头，可能会有相关信息
3）HTTP响应中的内容类型：Spring Boot应用程序通常会返回JSON、XML或HTML等格式的数据，这些数据的Content-Type头可以用于识别使用Spring Boot框架的应用程序。

thinkphp

1）查看网站源代码：在网站上按下F12打开开发者工具，查看源代码中是否包含ThinkPHP的关键词，例如thinkphp、ThinkPHP、TP、think_var等。
2）查看URL结构：ThinkPHP的URL通常采用/模块名/控制器名/方法名的结构，例如/index.php/home/index/index，并且URL中通常包含参数和标识符。
3）查看HTTP响应头：可以使用浏览器扩展或开发者工具查看网站的HTTP响应头中是否包含X-Powered-By: ThinkPHP等ThinkPHP特有的响应头。
4）查看ico图标，thinkphp官方源码自带图

Laravel

1）查看HTTP响应头：在浏览器中打开目标网站，使用开发者工具查看HTTP响应头，如果响应头中包含X-Powered-By: Laravel或者X-Powered-By: PHP/7.x.x Laravel或者Set-Cookie: laravel_session等信息，那么该网站很可能是基于Laravel框架开发的。

2）查看URL路由格式：Laravel框架的路由采用了RESTful风格的URL路由格式，通常包括HTTP动词、URI和控制器等信息，例如：GET /users/id，如果目标网站的URL路由格式符合这种规则，那么很可能是基于Laravel框架开发的。

3）查看HTML源代码：在浏览器中打开目标网站，查看页面的HTML源代码，如果其中包含Laravel框架特有的Blade模板引擎语法，如或者@for等，那么该网站很可能是基于Laravel框架开发的。

目标资产收集思路

明确搜集目的：信息收集的最终目的是为了获取相关权限
1）收集目标站点特征信息
2）拿特征信息去黑暗引擎中搜索，由大及小，搜索点：title、domain -> fid、icon-hash -> c段
3）域名及真实IP搜集、搜不出就从子域名入手
4）用拿到的真实ip，去fofa匹配c段，c段出来结合证书一起看，证书看组织、域名、邮箱是否与目标相关、不相干直接pass
5）google、社交平台搜集和目标相关的信息、如邮箱、其公司人员在网络上的痕迹等
6）github上也可以尝试搜集一下，可能有账号、源码泄露
未完待补充

注意点：
邮件服务器及vpn类的设备
ssl证书的组织、域名、邮箱
熟悉目标的提供的服务和产品、在fofa出来的资产中匹配、不相干的不纠结，直接舍去。
