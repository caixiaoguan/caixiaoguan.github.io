域用户guan1使用 net use \dc.guan.com\ipc$ 命令连接

本地：

域控net use 域用户

域控使用net use 连接域机器，会有一个凭据验证记录，验证自己

在域机器中也会有两个日志记录，一个是特殊登录，指明权限；一个是登录，指明对方（域控）的用户、使用的认证协议、ip等

域用户net use 域用户

域控会有一个凭据验证，审核webserver 是否有权限访问guan1

在webserver本地上无windows日志记录

目标guan1的日志记录上会有一个登录记录，包含登录对象、采用的验证协议、IP等

net use 会话和本地登录的区别

本地登录会先有两个kerberos 服务票证请求记录，一个来自DC$，一个来自krbtgt账户，随后紧跟一个登录记录，用的是kerberos

而net use 会先有一个凭据验证记录，随后紧跟一个登录记录，用的是NTLM

atexec.py

域控会有两个凭据验证记录

目标机器会有两个特殊登录、两个登录记录，特殊登录为新登录分配权限

wmiexec.py

域控会有4个凭据验证记录

目标机器上会有四个特殊登录，四个登录记录

psexec.py

域控会有四个凭据验证记录

目标机器同样是4个特殊登录，四个登录记录，但会多两系统记录，一个是服务创建，一个是服务运行

smbexec.py

域控只有一个凭据验证记录

目标机器会有一个特殊登录和一个登录记录，同时会有一个服务创建（\127.0.0.1\c$值得关注），一个服务超时错误（应该偶然事故）

secretsdump.py

目标直接就是域控，先是会有一个凭据验证，验证administrator 身份，紧接着是特殊登录为新登录分配权限，登录，以及导出hash要用到的一些目录服务操作，最后是两个注销记录

kerberos枚举

默认是不会在域控有任何日志的，毕竟只是kerberos的as_req，但是如果开启了日志审核，则会有成功事件4768，失败事件4771，且实战还是要尽量避免枚举，特别是内网敏感的项目，不然容易提前出局。

dcsync

会有一条4662，一些edr会特别关注该事件的来源ip，如果不是来自其它辅域控，会有相应警报。

总结

（1）本地登录使用的是kerberos认证

（2）net use 和dir，若用的ip 则使用的是NTLM认证，若用的机器名使用的是kerberos认证

（3）使用net use和dir除了域控外都不会本地安全日志记录，仅在目标和域控存在相应记录

（4）域控会记录域中所有凭据操作日志，因为所有的凭据认证都会通过kerberos或NTLM协议向域控进行认证

（5）各工具登录、注销啥的都会在域控和目标机留下记录，像psexec和smbexec处了安全日志有记录外，本地的系统日志还有服务创建、运行相关记录；secretdump提取hash需要用到目录，会在域控留下大量明显的日志。kerberos枚举与喷洒以及dcsync要根据实际情况合理使用，不然仍会成为监测的关注点。
